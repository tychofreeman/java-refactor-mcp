# The tool definitions in DEFINITION_OVER to the 1,700-character limit

- **Item:** roadmap item 523, the owner's request of 2026-11-16 (after #675 did `move`)
- **Date:** 2026-11-16
- **Branch:** tool-descriptions-trim

## Plan

Text only, as `move-description-trim.md`: each definition measured as `tools/list` sends it. Keep
one example per route and the addressing hints the schema lacks; cut refusal rules, what every
tool shares (1-based lines, type checks), and what an argument and the description both say
(usually the argument's copy goes, the description keeping the example). Then drop each tool that
fits from `ServerTest.DEFINITION_OVER`.

## Notes

- read: `DEFINITION_OVER` on a fresh main held 14 tools, not the 5 the request named:
  `add_parameter` 3,374 down to `inline` 1,737 (its entry said 1,760).
- read: every definition from the jar's `tools/list` over stdin; the size of each with all text
  removed (its schema alone) set the budget: `add_parameter`'s schema is 897 characters, which
  leaves 803 for its description and 13 arguments' texts.
- plan: drafts kept in a scratch Python file (description and argument texts per tool) and
  measured on the dumped JSON until each was under 1,700; the same file then wrote one batch:
  `replace_declaration` of each `Tools` field (text block and argument literals changed, the rest
  as read through `inspect names`) and `replace_text` of four shared `Arg` constants. The
  measured sizes matched the rebuilt jar's exactly.
- Shared constants shrunk: `METHOD_LINE` and `METHOD_COLUMN` ("1-based" is in the instructions),
  `IMPORTS` (shorter wording), `BUILD` (the entry list, which `insert_statements`' examples show;
  it keeps what they do not: a loop's `name` and `type`, a guard's `message`).
- `ServerTest.DEFINITION_OVER` by `replace_text` (a few lines of code).

## Per tool (old -> new characters; what went, what stayed)

- `change_signature` 2,596 -> 1,693: went: the void bodies' rewrite (`return x;`, `r -> {}`), the
  method-reference clause, how a catch is placed, the line hint (argument says it), callers'
  options spelled out (now in its argument: `propagate (default), catch or refuse`). Kept: the
  return type and throws example, propagation up to `stop_at` or `Runnable.run()`, "other calls
  are not edited".
- `insert_statements` 2,518 -> 1,690: one example per entry kind kept (call with `into`, new,
  loop, guard, guard_null, string); went: "the body's entries use the loop's variable", a Map's
  `entrySet()`, the guard's message example, "the result names each type".
- `remove_parameter` 2,349 -> 1,686: all three examples kept (plain, field value, expression
  value), shortened; went: "use it last when taking a feature out", the side-effect rule
  (a refusal), the addressing sentence (arguments say it), the long `value` argument text.
- `change_type` 2,257 -> 1,692: field, parameter (new short example) and bound examples kept;
  went: "Identify the field as Type.field, a top-level class of the file", the line sentence.
- `type_switch_to_method` 2,154 -> 1,686: the type switch, the statement/if-chain route and both
  enum forms kept; went: `@Override public double area()` spelled out, "a default method of an
  interface", the enum default's rule and the abstract declaration.
- `replace_statements` 2,114 -> 1,596: all routes kept; went: `while (more)` from the surround
  list, the line wording the arguments repeat.
- `extract_type` 2,048 -> 1,688: three examples kept, the record one without repeating
  `members`/`new_type`; `value_semantics` left to its argument.
- `extract_variable` 2,029 -> 1,564: went: the addressing paragraph (arguments say it), the
  literals-and-constants rule from `as` (a refusal).
- `fold` 1,897 -> 1,685: every example kept (expression, void statements, instance method,
  near-duplicates, merge recipe); went: the `line` sentence (its argument says it) and "a match
  the call would not reproduce is left, and the result says why".
- `extract_function` 1,852 -> 1,679: went: "declared after the one they are in" (layout),
  "Behavior is unchanged", "as inspect numbers them", the `doc` sentence.
- `batch` 1,801 -> 1,684: went: "planned from one read", the client-name aside, the `retry`
  argument's repeat of the description's three forms.
- `add_declaration` 1,776 -> 1,589: placement by kind said in four words; `implement`'s detail
  left to its argument.
- `inline` 1,737 -> 1,663: went: `keep_function` from the description (its argument), "1-based".
- `add_parameter` 3,374 -> 3,338 (shared constants only): not fitted. With every example cut and

## Measured

Not measured: the session-log hook is not loaded here. 2 tool calls wrote Java (one batch of 17
steps, one `replace_text`), 0 hand edits. The batch was generated by a scratch script from the
measured drafts, not typed: the escaping of the text blocks and the measurement had to agree.

## Assessment

Through the tools. `replace_declaration` of a whole field reprints the code around the text,
which `replace_text` per literal would not; with 13 fields and about 60 literals, one generated
batch was the cheaper and less error-prone route.
